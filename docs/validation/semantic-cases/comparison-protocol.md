# 本轮新输入与固定流程对照方法

这是同一开发协作团队的小规模内部验收与一次执行策略消融，不是独立第三方评测。新输入作者知道上一轮六例暴露的问题类型，也阅读了现有资料和经营边界；24条新句子未交给实现负责人调试，冻结后不改题。原六例只作开发回归，首次失败记录保留。

## 预声明与计分

- 24条输入的SHA256与类别清单保存在[input-freeze.json](input-freeze.json)，分为12条完整交付、6条必要确认、6条正确拒绝。
- 三类分别报告分母、通过数、失败编号和实际状态，不用一个“拒绝得越多越安全”的综合数字替代交付能力。完整交付题停在确认、拒绝或模型故障都判失败；正确拒绝必须给出预声明的可核对冲突。
- 完整交付检查内容类别、指定事实状态、明确偏好、手作与总时长、金额与日程复算、教学校验、来源定位、双版预览、确认门禁和正式双版导出。测试脚本显式模拟负责人点击确认，只检验接口保护，不声称真实经营人员已审核。
- 教学内容的事实扫描仍来自同一模型，并有程序引用/版本/字段绑定检查；这不替代独立文化专家复核。预声明事实片段按对应来源判断，其余生成内容的语义质量尚需人工复核。

## 两种执行策略

两种策略共享本轮同一版本的解析、数值范围归属、检索、逐句核验、求解、确定性偏好排序、教学生成、教学扫描和导出工具；使用同一个Qwen3-14B Q4_K_M本地模型、同参数、同资料和经营快照。不使用上一版已知存在问题的代码人为制造优势。

**固定流程（fixed）**：共享阶段按固定顺序各执行一次。保留纠错文字再次核验这一必需业务阶段和全部安全门，但不对结构失败再次请求，不根据歧义/选择/教学失败反馈启动追加修复。失败如实停止或等待确认。

**有界智能体（agent）**：相同初始阶段，并允许以下有界反馈分支：

1. 单阶段结构不合法时最多追加一次结构化请求。
2. 偏好提取给出阻断性歧义时，允许一次阻断理由复核，区分编辑说明、现有条件可计算的资源问题与真正需要澄清的需求。
3. 方案校验失败时最多两轮修订，不改变程序排序、报价、人数、教师或场地边界。
4. 教学失败时，只有在预算允许且确有可修订内容时，再生成一次文本并重新扫描；错误原候选保留。若扫描仅有字段内部矛盾（已有文化前提却判为无新事实）且所有条目未标记不支持/资料不足，允许一次扫描契约修复；不把原错误扫描塞回提示，内容与来源摘要必须保持一致。明确无依据的结果不能通过重复投票放行。

始终最多8次模型调用，教学至多一次修订；正常方案与教学首次通过时不额外调用。该补充在旧六例开发回归过程中确定，在24条新输入首次运行前预声明。初始输入冻结记录里的简略策略描述仍保留，最终实现冻结另存源码和本说明的哈希。

## 执行与复核

每个案例分别运行agent与fixed一次；第1对AB、第2对BA交错，以减少顺序偏差。两次使用相同请求、资料版本和经营快照，逐对记录哈希。模型参数为temperature=0、seed=42、num_ctx=8192、num_predict=2300、think=false；这不保证不同硬件或运行器版本输出逐字相同。

实现稳定后先运行`tests/acceptance/run_semantic.py --freeze`，再运行`--run`。runner在独立SQLite中调用真实本地模型，通过内存API执行真实业务，既不访问当前演示数据库，也不替换为假模型。受保护实现或资料发生变化会立即停止。

原始运行、模型输出、检查结果、首跑清单保存在本目录的`first-run/`；完整双版HTML保存在仓库忽略目录`artifacts/semantic-acceptance/packs/`并记录哈希。首次文件采用不可覆盖方式写入。进程中断或失败也保留；后续修复必须另行记作回归，不能更换首轮结果。

报告成功与真实失败、每类完成能力、调用数和本机耗时。若两种策略结果相同，直接说明没有观察到通过率差异；若不同，也仅支持这些输入和这一执行设置下的差异，不能推断Agent普遍优于固定流程。耗时受缓存、系统负载和首调用顺序影响，不作速度优势承诺。
