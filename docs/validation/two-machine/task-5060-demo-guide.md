## 目标

接下来一周有 3 场 20 分钟的线上从业者访谈，其中 8 分钟由 5090 共享屏幕，按三幕操作真实系统；决赛答辩也会用到。操作者紧张时容易点错或漏步，所以加一条“照着点就能讲完”的引导。引导只做填入和定位，结果完全来自真实运行。

## 改动

1. **只在真实 API 模式出现。** `live.js` 在 `file://` 下直接返回，连接不上 API 时也不会进入 `setupLive`，所以预设模式和“服务未连接”页面都不受影响。
2. **开关**：运行状态栏“投屏大字”旁新增“三幕演示”（`#demoGuideToggle`，`aria-pressed`），默认关闭。打开后，工坊页和编排页顶部各出现一条窄引导条（`#demoGuideStudio`、`#demoGuidePlanner`）。引导条标明“演示引导 · 结果以真实运行为准”和“只填入与定位，不代为提交、确认或导出”。桌面端吸顶，手机端随页面滚动，避免遮挡内容。
3. **三步按钮**（运行中或其他操作进行中时禁用）：
   - **第一幕 · 讲对 —「填入主线案例」**：切到工坊页，把展示输入选为“主线案例 · 蔚县剪纸地域纠错”，沿用原有预设函数填入地域、项目、文案和该案例的表单条件，焦点移到“核验并编排体验”并高亮。
   - **第二幕 · 排好 —「填入：不要茶歇，多留手作时间」**：把这句话写进“这场体验，您有什么想法？”，编排方式设为“按需求组合活动模块”，切到编排页，高亮“按当前条件重新编排”。还没有上一次方案时，会提示先完成第一幕。
   - **第三幕 · 守住 —「定位到素材撤回」**：切到编排页，滚动到“文化使用边界”，高亮第一条素材的“撤回使用”。操作者撤回后，若服务端把当前运行标为失效，再高亮“依据最新资料重新核验”。
   - 高亮在操作者点下目标按钮时清除。填入会把当前结果标为“输入已变化”，与手动修改输入的处理相同。
4. **✓ 只看真实运行状态**，不看按钮是否点过。历史回放不计入。每一步一旦由某次真实运行满足，就记下该运行的任务号并保持 ✓，刷新页面后清空：
   - 第一幕：当前运行至少有一条已判定陈述的 `status` 为 `contradicted`。
   - 第二幕：当前运行的 `comparison.after.craft_minutes` 大于 `comparison.before.craft_minutes`，且运行没有失败；✓ 后面显示实际分钟数。
   - 第三幕：目录中有素材不是 `available`；当前运行的 `parent_id` 是一次已失效的运行；当前运行已结束，状态为 `awaiting_review` 或 `confirmed`。
   - 运行失败、需要确认或需要补充条件时，引导条给出一句提示，例如“本次真实运行失败，不显示 ✓；引导不会用预设结果替代”，并且不显示 ✓。
5. **首页三张幕卡**：真实 API 模式下，点击后照常进入对应页面，同时打开引导、标出对应一步，并把焦点放在该步按钮上。
6. **样式**：沿用纸白底、墨绿边框和朱红左边线；高亮是朱红描边加轻微脉冲，系统设置减少动态效果时不脉冲。引导条内中文字号不小于 12px。

## 第二幕的对比基线（无模型推算，仅供参考）

方案对比的“上一次方案”取上一次运行保存的 `plan`（确认后为已确认方案）。编排器是确定性的，因此在不调用模型的情况下，用第一幕预设条件（8 人、¥160、150 分钟、模块模式、茶歇“灵活安排”）调用 `solve_plans`，按总价排第一的可行候选是“简述 + 基础手作”：手作 50 分钟、¥574、全程 70 分钟。加上“多留手作”（不含茶歇、`maximize_craft`）后，排第一的是“简述 + 深度手作 + 手作延长”：手作 80 分钟、¥796、全程 100 分钟。

这只是程序推算，不是真实运行结果。实际推荐方案和是否出现 50 → 80，以 5090 真实运行为准。首页“50 → 80”和三分钟讲稿“720 → 796”的基线带茶歇，并经过人工选择，与本引导的默认路径不同，以页面实时显示为准。

## 请 5090 验证（真实模型）

在隔离 worktree 和独立数据库中，按 [5090 真实验证提示词](../../development/prompt-5090-validation.md) 完成第 1 至第 3 步的标准回归。`<候选分支>` 为 `dev/5060-demo-guide`。然后按 [访谈操作卡](../../demo/interview-demo-runbook.md) 完整走一遍三幕，每一步只跑一次，首次结果就是结论：

1. 打开 `http://127.0.0.1:<端口>/`，刷新页面。点“三幕演示”，确认工坊页和编排页顶部都出现引导条，并写有“演示引导 · 结果以真实运行为准”。
2. **第一幕**：点“填入主线案例”，再由操作者点“核验并编排体验”。记录 run_id、状态、模型调用次数和耗时。预期：“阳刻为主”判为与来源矛盾，修订为阴刻为主；第一幕出现 ✓，后面带同一 run_id 的前 8 位。
3. **第二幕**：点“填入：不要茶歇，多留手作时间”，再由操作者点“按当前条件重新编排”。记录 run_id、方案对比的手作分钟、全程分钟和总额。预期：手作分钟增加，第二幕 ✓ 显示的分钟数与对比卡一致。若没有增加，如实记录两次运行的推荐方案，交回 5060，不要手动挑方案凑结果。若出现“文字与表单冲突”，也如实记录。
4. **第三幕**：点“定位到素材撤回”，由操作者点“撤回使用”。确认旧结果显示失效、确认和导出被禁用、“依据最新资料重新核验”被高亮；此时第三幕还不应 ✓。点重新核验后记录新 run_id 和 `parent_id`。预期：新运行完成后第三幕 ✓；预览游客版时不再使用撤回素材。演示结束后，在页面上点“恢复可用”，把素材恢复。
5. 整个过程中，引导按钮不应自己发起运行、确认或导出：只有操作者点击“核验并编排体验”“按当前条件重新编排”“依据最新资料重新核验”时才产生新任务。
6. 在 1440 和 390 宽度下，打开和关闭投屏大字，查看引导条：没有遮挡、溢出或截断，中文不小于 12px。
7. 直接用文件方式打开 `frontend/prototype/index.html`：没有“三幕演示”按钮，预设模式与之前一致。
8. 结果记录按 `two-machine-result.schema.json`，写入以上 run_id、调用次数、耗时、三个 ✓ 是否出现以及首次失败；原始 JSON 和截图留在 `artifacts/`。

## 已知限制

- 5060 没有真实模型，三个 ✓ 的出现只用拦截 API 的假数据检查过逻辑，不能当作真实效果。
- 第二幕 ✓ 依赖第一幕的推荐方案手作分钟少于第二幕。上方推算显示默认路径是 50 → 80，但实际以真实运行为准。
- ✓ 在页面会话内保持，刷新页面才清空；每场访谈开始前需要刷新。
- 引导不在 Windows 原生 Edge 上检查过；5090 验证时以 Edge 为准。
