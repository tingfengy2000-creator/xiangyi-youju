## 5090 第二次首次失败（`917d90b`）

- 第二幕修复生效：受众 student，教学通过，手作 50→80 分钟、574→874 元。
- 讲解词草稿（老年人）由本地模型写成，送去核验时失败：“模型拆解遗漏原句或新增了未知句子”。记录见 [handoff-rehearsal-5090-film-capture-917d90b.json](handoff-rehearsal-5090-film-capture-917d90b.json)。
- **原因**：程序在逗号处切分长句。草稿里“河北省蔚县的剪纸艺术，有着悠久的历史。”“一张宣纸和一把刻刀，是制作剪纸的基本工具。”切开后，“有着悠久的历史。”和“一张宣纸和一把刻刀，”都是半句。模型把它们并进了相邻分句的 query（例如 s8 的 query 就是“基本工具是否为一张宣纸和一把刻刀”），只返回 6 条，程序要求 8 条一一对应，于是整次失败。评委自己输入带逗号的长句时也可能遇到，所以这是业务缺陷，不只是采集问题。
- 采集脚本随后又去等一个隐藏的结果区，30 秒超时，掩盖了真正的状态。

## 第二版修复

1. `backend/workflow.py`：
   - 模型漏掉的若是**同一原句里的半句**，程序按原文把它补回成一条独立陈述，沿用相邻分句的 kind 和 query，再单独检索、单独核验。已返回的分句一字不改，也不合并，程序不会把任何陈述标为支持。
   - 仍然失败：整句都没有返回、重复的分句、模型新增的未知句子。
   - 模型抄写分句时只允许标点和空格不同，核验对象一律用程序切出的原文。
   - 补回的半句记在运行的 `segment_recoveries` 里，事件流写明“程序已按原文补回并单独核验”。
2. `scripts/capture-film-footage.cjs`：讲解词一步改为与三幕验收同一组输入（青少年学生、5 分钟），这条路径在 `370f7db` 已有真实运行通过；草稿核验和英语阻断都先断言状态，失败时直接报出真实状态，不再超时。
3. 测试：用 5090 的原文和模型原始输出做单元测试，s2、s7 按原文补回；整句遗漏、重复、未知句子仍失败；只差标点可接受，改写或改意不接受。
