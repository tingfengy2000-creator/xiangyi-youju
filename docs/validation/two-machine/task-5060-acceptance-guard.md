2. **统一字号检查** `tests/e2e/legibility.cjs`：遍历可见文本节点，只要含有中文（混排也算），渲染字号必须不小于 12px。
   - `npm test`：预设模式三页 × 1440/390 都检查。
   - `live-workflow` 无模型分支：三页 × 1440/390 × 投屏开/关，三幕引导开启。
3. **正式验收脚本** `npm run test:demo-guide`（`tests/e2e/demo-guide-acceptance.spec.cjs`），一次跑完以前需要人工和临时脚本完成的全部检查：
   - **前置检查（不调用模型）**：模型就绪；所有素材可用；没有运行中的任务。不满足就停止，不做任何修复。
   - **首页**：首次载入 0.5 秒和 4 秒时都没有提示条，然后截静止画面。
   - **三幕各只提交一次**：每次引导点击后等 1.5 秒，写请求必须为 0；只有模拟操作者点击“核验并编排体验”“按当前条件重新编排”“依据最新资料重新核验”时，才各产生 1 个提交。三个 ✓ 必须带对应任务号，第二幕的 ✓ 必须与方案对比的分钟数一致。撤回后检查旧运行失效、确认和导出禁用，并确认这时第三幕还没有 ✓。
   - **可读性矩阵**：2 种宽度 × 投屏开/关 × 引导开/关 × 3 页，共 24 组，检查横向溢出和中文字号。
   - **恢复素材**：在页面上点“恢复可用”。脚本中途失败时，`finally` 也会通过接口恢复，并记入结果。
   - **文字需求阻断**：重新载入页面，保持全部默认条件，只把“这场体验，您有什么想法？”替换为给定短句，各提交一次，并保存实际请求体。脚本会断言请求体里 `note` 只有这句话、`planning_mode=modules`、`tea_preference=any`。
   - **首页三图**：全部通过后才写入 `HOME_SCREENSHOT_DIR`。
   - **任何一步失败**：立即停止，不重试；保存截图、引导条 DOM 和 `result.json`（含全部写请求、任务号、调用次数）。
