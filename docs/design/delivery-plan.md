# 实施与参赛展示清单

## 1. 目标与范围

入围全国决赛是当前唯一竞赛目标，前端质感是最高设计要求。开发只围绕主方案，不同步建设用能智核。每增加一个功能，都应说明它改善哪项评审证据、需要多少新增数据和验证工作。

本次已有：三页设计原型、真实变化的演示账本/约束、架构与实现设计。下一阶段才是模型与后端实现。不要把当前原型作为完整AI产品提交。

## 3. 必做与取舍

**P0必须完成**：三页视觉、真实本地推理、地域检索、来源定位、结构化结果、约束与金额校验、有界任务状态、体验包、强基线和独立测试、连续演示录像。

**P1有时间再做**：第二个完整非遗专题、手机体验卡独立分享、资料变化后的增量复核、线下志愿者试用。PDF导出可用浏览器打印方案，避免先增加复杂排版工程。

**暂不做**：支付、真实预约、多租户账号、全国地图、数字人、VR、复杂知识图谱、大量角色协作、训练/微调、自动营销发布。这些会增加费用、授权或数据门槛。

## 4. 三个展示故事

| 故事 | 演示动作 | 评审看到的证据 |
|---|---|---|
| 地域混淆 | 错稿→来源→最小修订→讲解卡 | 文化知识有出处，Agent做了实际查证 |
| 计划冲突 | 调低预算/时间或超容量→发现无解→确认调整→再验证 | 模型调用工具解决任务，没有编造可行计划 |
| 价值流向 | 改人数/活动/材料方式→日程与账本变化 | 经济与生态进入产品逻辑，假设可检查 |

预设演示稿要精修排版，但保留“人为植入问题”的说明。真实在线推理、缓存命中和历史回放使用不同状态，不用回放冒充实时运行。

## 5. 初赛材料结构

1. 一页项目概览：用户、痛点、完成闭环、三张核心界面。
2. 一页创新机制：主动查证、约束式编排、来源绑定与最小修改。
3. 一页架构：本地模型、Agent工具、确定性检查、人工确认。
4. 两页验证：同模型强基线、独立测试、真实结果和失败案例。
5. 一页乡村价值：本地服务支出路径、生态规则、文化保护与社区控制。
6. 实现与复现材料：源码、依赖锁、模型标识/下载说明、资料版本、运行说明。

按照本届实际模板调整，不将上述页数解释为官方格式要求。按官方匿名要求检查学校、个人标识及附件内容；报名系统所需身份字段与匿名作品正文分别处理。

首屏美观决定理解入口，完整证据决定能否经受评审追问。不要在首页放未经实验的准确率、已服务村落数、虚构合作单位或增长金额。

## 6. 演示节奏

初赛可准备约3分钟紧凑产品录像（这是建议，不是已核实的视频时长硬要求）：20秒问题与主视觉；50秒事实审校；50秒计划冲突和修复；30秒账本；30秒实验与运行条件。

如进入决赛，准备10分钟主版本和8分钟压缩版。官方现场演示答辩窗口为8—15分钟，包含陈述、演示与提问，具体分配需服从现场安排。[官方评审方式](https://cpipc.acge.org.cn/cw/contestNews/detail/1/2c9080189ef4ecee019f036d22cf5bcb?page=0)

现场主线：界面与问题1分钟，案例A/B/C共4分钟，架构1分钟，真实实验1分钟，乡村价值与后续落地1分钟，其余预留提问。不要只演精修成功案例；至少准备一个来源不足或计划无解的诚实处理。

## 7. 交付前检查

- 三页在桌面与手机可用，关键文字无裁切，金额/百分比一致。
- 任意用户输入得到真实后端结果；预置演示与模型运行分开标记。
- 所有事实引用可定位，文化差异不被归一化抹去。
- 计划违反约束时无法被显示为“已通过”。
- 经营和容量数据注明来源；没有实际合作时保留演示标签。
- 结果表可由冻结脚本复现，模型/提示词/资料版本可追溯。
- 零API费用路径在断网状态下可运行；故障回放如实显示。
- 案例图片、纹样、字体和资料使用范围已核对。

以上检查用于实现阶段。本次已完成的是设计原型的页面、交互和算术检查，尚未完成模型及业务性能验收。
