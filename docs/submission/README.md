## 提交前仍需补齐

1. 实际队员、匿名团队名称、分工经历和指导关系。身份栏目与指南匿名要求的填写口径需按平台或组委会确认；不得将培养单位或指导教师身份放入评审正文。
2. 对本轮留存失败继续用新的开发输入调查，避免把已验收题目当作新的未见测试。当前仍缺独立第三方评测，不称独立评测；程序测试数量不替代真实任务效果。
3. 一位文化资料核对者及一位活动组织者的真实反馈、知情同意、流程记录与使用授权。当前没有合作单位、传承人背书或真实订单。
4. 目标用户访谈、真实人工流程对照及规范的国内外研究/产品比较。市场规模、付费意愿、收费标准、收益和净利润均无证据，继续留待补。
5. 依据赛事成熟度定义核定技术成熟等级。简表没有自行勾选等级，也未选择“国内领先”等缺乏证据的先进性结论。
6. 核实公开开发仓库与指南“首次发表”条款的适用关系。保持现有可见性；后续另从确认版本生成匿名源码证明包，剔除`.git`、账号、个人路径、日志、数据库与密钥。
7. 完成最后版Word逐页渲染检查，并在提交前核对平台及官方后续通知。未核实的附件计划日期不作为最新日程承诺。

## 模板与字数检查

四份原件SHA-256与[已核对的附件清单](../development/competition-submission.md)一致。构建时遇到原件变化会停止，不把另一个版本当作同一模板。保留原页尺寸、页边距、字体字号、章节层级、表格及合并关系，只填正文槽位并清除原模板作者及公司元数据。必要排版修正为：已填文字改用黑色，简表空白写作区行高自适应、删去赛道栏多余空段，避免“立项思路”标题孤置页末；说明书移除模板末尾的空白分页；标题与正文保持衔接、来源段采用左对齐。未缩小字体。

十四个限字栏目均通过保守计数：去掉空白后，中文、标点、数字及每个英文字母均逐字符计入。上限分别为简表300/300/600/300，说明书2000/3000/3000/500，商业计划书200/200/2000/2000/2000/500。具体计数见构建清单，后续修改会重新检查。

## 再生成方式

先修改`draft-content.json`，然后使用包含`python-docx`和`lxml`的Codex文档专用Python运行：

```powershell
& <文档专用Python路径> scripts/build_submission_drafts.py --templates-dir <原附件目录> --metrics docs/submission/validated-metrics.json
```

脚本不修改原附件，不调用模型或外部API。简表五项指标可通过`--metrics <已复核JSON>`明确传入，格式为`{"form_rows": [["指标名称", "指标值", "参照值", "提升度", "参照对象"], ...]}`，共五行；脚本不会推断或补造测量值。修改正文或指标后，需要重新渲染检查并更新输出哈希。

经济、文化和生态相关陈述的共同边界是：本地服务报酬为演示毛额，不是村民净增收；工具复用和纸材数量是活动设计要求，不是已测节纸或减排效果；文化事实经来源核对，不代替地方文化人员审定或素材授权。
